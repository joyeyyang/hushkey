# M7 那一輪的真機驗收清單（2026-10-30）

> 存在的理由和 `ios-pip-device-checklist.md` 一樣：**模擬器驗不了**。
> 這一輪新增的五件事裡，四件在模擬器上只驗到了程式路徑（`simctl` 不能點鍵盤、
> 不能點按鈕、不會鎖螢幕、沒有真的手機網路），第五件（廣播擴充）在模擬器上
> 根本不會跑。在這份清單被填完之前，專案裡沒有任何一處可以宣稱它們「已驗證」。
>
> 目前狀態：**未在真機執行**。模擬器上已驗的部分寫在每一項的「模擬器已驗」列。

## 0. 前置

| 項目 | 要求 |
| --- | --- |
| 建置 | 簽章建置（App Group＋鍵盤都要 entitlement） |

| 鍵盤 | 設定 › 一般 › 鍵盤 › 鍵盤 › 新增「Hushkey」，並開啟**允許完全取用** |

## 1. 貼上前確認（附錄 O.2）

設定 › 插入 › 「貼上前確認」開啟。四個動作都要做。

### A. 文字不會自己進游標

1. 開「備忘錄」，叫出 Hushkey 鍵盤，按麥克風說一句話。
2. 預期：鍵盤上出現面板，句子在狀態列上；**備忘錄裡沒有出現任何字**。
3. 預期：按鈕是「重說一次／丟棄／插入」。

| 結果 | 證據 |
| --- | --- |
| 未驗 | |

模擬器已驗：面板與三顆按鈕的樣子（`ios-keyboard-confirm.png`）。

### B. 插入

1. 承 A，按「插入」。
2. 預期：整句出現在游標處（不是只出現一部分），面板收起，鍵盤高度回到 216pt。
3. 預期：狀態列顯示「已插入 N 字」。

| 結果 | 證據 |
| --- | --- |
| 未驗 | |

### C. 重說一次

1. 承 A，按「重說一次」，說另一句話。
2. 預期：面板重新出現，狀態列是**新**的那一句。
3. Mode 2（小窗）下：預期不跳 App；Mode 1 下：預期跳到 Hushkey 錄音，回來時
   面板已經開好。

| 結果 | 證據 |

| 未驗 | |

### D. 丟棄

1. 承 A，按「丟棄」。
2. 預期：備忘錄沒有新增任何字，狀態列顯示「已丟棄，沒有插入。」，接著回到
   「按麥克風開始說話」（**不會**把剛才那句顯示成已插入的樣子）。

| 結果 | 證據 |

### E. 面板開著時，鉛筆不動

3. 長按鉛筆：預期等於「重說一次」。

### F. 關掉開關之後回到原本的行為

1. 關掉「貼上前確認」，再說一句。

## 5. 會議模式的錄音端（還沒做，先不動）

這一項要 ReplayKit 廣播擴充：新 target、`com.apple.broadcast-services-upload`、
使用者的「螢幕與系統音訊錄製」授權，而且**模擬器完全驗不了**。目前 App 沒有這個
target，所以這一格現在沒有東西可以點——真機清單上刻意留空，免得看起來像漏跑。
